# Laravel-workbench

Локальное Laravel 12 приложение в том же репозитории и рабочем дереве. Его единственный UI-пакет — корневой `aestetic/ui`, подключённый через Composer path с symlink. Копия кода библиотеки не создаётся. Приложение не использует Anilau, БД, Vite, Node или CDN.

Каталог читает `catalog/components.json` именно из подключённого пакета. Описания, правила, API, статусы и список превью не дублируются в workbench. Каждый сценарий — файл `catalog/examples/<id>.blade.php`: этот же файл исполняется через Blade и показывается в исходном коде примера. Ни HTML-копии компонентов, ни renderer дизайн-прототипа здесь не используются.

## Подготовка на новом компьютере

Из каталога `workbench` (PHP 8.3+ и Composer):

```sh
cp .env.example .env
composer install
php artisan key:generate
```

`cp` нужен только при отсутствии `.env`; существующий файл и ключ сохранять. Composer устанавливает Laravel и локальный пакет, выполняет стандартный package discovery и копирует готовые ассеты пакета в `public/vendor/aestetic-ui`. Это локальная подготовка приложения, без внешней публикации. `composer.lock` фиксирует зависимости приложения. Composer-scripts не запускают тесты, lint, сборку ассетов или сервер.

## Просмотр

Сервер запускается отдельно, по поручению пользователя:

```sh
php artisan serve --host=127.0.0.1 --port=8010
```

После запуска адрес каталога — [http://127.0.0.1:8010](http://127.0.0.1:8010). Браузер автоматически не открывается. Адрес существующего дизайн-прототипа `aesteticui.test` и его Valet-привязка не изменяются.

В каталоге:

- Верхние разделы «Компоненты» и «Подключение». Обзор и боковая навигация группируют 14 атомов по задачам; Scope/Page/Assets вынесены в основу интерфейса.
- 26 сценариев для 17 experimental-контрактов: состояния кнопок и ввода, одиночный Select, checkbox/radio/switch, статусы, Lucide, изображения и структура страницы.
- Переключатели light/dark/system, comfortable/compact и ширины превью (вся доступная ширина / до 360 px). Выбор хранится в URL и сохраняется при переходах.
- Изолированные iframe с реальными компонентами и исходным Blade того же фрагмента.
- Назначение, правила UI/UX, размещение, альтернативы, подключение, API и slots из общего реестра. Planned-записи остаются в реестре и доступны по прямым ссылкам без выдуманного preview.

Ширина 360 px ограничивается доступной шириной экрана. System следует настройке ОС; светлая и тёмная темы не требуют JavaScript. Фокус/hover можно смотреть на настоящих элементах; каталог не имитирует их статическими классами. Submit в примере перезагружает только свой iframe. Демонстрационные действия Page не выполняют бизнес-операций.

Workbench использует настоящие Scope/Page/Button/Assets для собственной оболочки. Его навигация, переключатели просмотра, API-таблица и контейнеры примеров — служебная разметка каталога; они не объявляются реализациями ещё planned Navigation/Tabs/Table/Panel.

## Сценарии и обновления

Добавлять сценарий одновременно с реализованным контрактом:

1. Создать `catalog/examples/<id>.blade.php` с вызовами реальных компонентов.
2. Добавить к компоненту в реестре запись `previews`: `id`, `title`, `description`, `height` (высота iframe в px).
3. Использовать в сценарии `$theme`/`$density`, если они нужны. Внешний Scope превью уже получает выбранные значения.

Идентификаторы ограничены латинскими буквами, цифрами и дефисом. URL не выбирает произвольный файл: компонент и сценарий разрешаются по реестру, planned-записи дают 404 для preview. Код и исходник читаются из одной фиксированной директории пакета. `wb-*` — локальные классы обрамления примеров, они оформляют только композицию демонстрации и не входят в публичный API библиотеки.

При изменении Blade/JSON их подхватывает symlink. Если изменён исходный CSS библиотеки, поставку `dist` нужно подготовить в отдельно разрешённом объёме; затем из workbench скопировать соответствующие ассеты:

```sh
php artisan vendor:publish --tag=aestetic-ui-assets --force
```

Не редактировать копии в `public/vendor`. Каталог использует manifest текущего пакета, поэтому копирование ассетов и изменение пакета должны быть согласованы. Изменения CSS самой оболочки находятся в `public/catalog.css` и не требуют сборки.

Сессии и cache используют array-драйверы; БД, миграции, очереди и внешние сервисы для каталога не требуются. Локальный `.env`, vendor, public-ассеты и runtime-файлы не включаются в Git. Workbench исключён из Composer-архива библиотеки.

## Граница готовности

Исходники приложения и 26 сценариев подготовлены. Локально установлен Laravel 12.70.1, зафиксирован composer.lock, пакет подключён symlink. Ранее выполнены discovery, копирование CSS и локальный запуск по поручению пользователя; текущие CSS/JS записаны в public-ассеты. Полная приёмка новых атомов не выполнялась.

Ранее по отдельному поручению сервер запускался и была открыта вкладка. Текущие новые атомы, навигация и взаимодействия не проверялись HTTP-запросами или в браузере; проверки/validation builds не запускались. Публикации нет. Experimental-статус и runtimeVerified=false сохраняются. [Новая структура и границы](../docs/atomic-catalog.md).

Основа bootstrap: [официальный Laravel 12 skeleton](https://github.com/laravel/laravel/tree/12.x). Контракты библиотечного подключения описаны в [installation.md](../docs/installation.md).
