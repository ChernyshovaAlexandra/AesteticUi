# Ползунки и прогресс

Основание — прямой запрос пользователя от 23 октября 2026. Визуальные ориентиры — [Slider](https://ui.shadcn.com/docs/components/slider) и [Progress](https://ui.shadcn.com/docs/components/progress) shadcn/ui. Реализация прототипа использует общие локальные renderers и CSS, без установки React/Radix.

## Ползунок

Slider выбирает одно числовое значение. `components.slider({ id, label, name, min, max, step, value, disabled, hint })` собирает общий Field, нативный `input type="range"` и видимую подпись значения. ID должен быть уникальным. Границы и шаг задаются валидными значениями приложения; min по умолчанию 0, max — 100, step — 1. Этот компонент не подменяет семейство Range с парой полей «от/до» и не реализует ползунок с двумя бегунками.

Дорожка — 6px, бегунок — 16px с нейтральной рамкой и лёгкой общей тенью. Заполненная часть использует основной цвет контролов, оставшаяся — нейтральную подложку. Текст значения имеет табличные цифры и русское форматирование десятичных дробей. Светлая и тёмная темы используют общие переменные `--control-*` и `--surface`.

`controls.enhance(root)` синхронизирует заполнение с фактическим `valueAsNumber`, учитывая min/max. События input/change и reset формы обновляют заполнение и подпись, не заменяя исходный input. При программном присвоении value вызывающий код должен отправить событие input/change либо повторно вызвать enhance. Дополнительные обёртки и подписки на каждый ползунок не создаются.

Нативный input сохраняет имя/значение формы, шаг, disabled, управление мышью, касанием и клавиатурой. Отдельное визуальное значение скрыто от screen reader, поскольку сам ползунок уже сообщает текущее значение. Фокус и hover меняют заливку бегунка без внешнего кольца. Недоступный ползунок сохраняет видимое значение и заполнение с пониженной непрозрачностью. Высота области взаимодействия — общая высота контрола, на мобильном минимум 44px.

## Индикатор прогресса

Progress сообщает выполнение операции, а не выбирает значение. `components.progress({ id, label, value, max })` принимает уникальный ID, подпись и необязательное числовое значение. Max по умолчанию 100; значение ограничивается диапазоном 0…max. Отображаемый процент вычисляется по этому диапазону, а ширина заполнения сохраняет точную долю.

Дорожка высотой 8px и заполнение имеют полностью скруглённые края. Процент расположен рядом с подписью. Роль progressbar связана с подписью через aria-labelledby; определённый прогресс передаёт aria-valuemin, aria-valuemax и aria-valuenow. Индикатор не получает tabindex или роль кнопки.

Если значение неизвестно, value опускается либо задаётся null. Вместо выдуманного процента показываются «Выполняется…» и движущийся сегмент; aria-valuenow отсутствует. При reduced motion сегмент неподвижен. Завершение, ошибка и отмена операции определяются приложением; этот renderer сам не запускает загрузку и не меняет состояние по таймеру. Для неизвестной доли используется неопределённое состояние, а для ошибки — отдельное сообщение системы.

Синие outline и focus-ring не добавляются ни ползунку, ни индикатору. Иконки этим компонентам не требуются.

## Примеры и граница готовности

В «Поля и выбор» показаны ползунок с шагом 5, минимальное и максимальное значения, disabled и дробный диапазон с отрицательной границей; прогресс — 0%, 60%, 100% и без известного процента. Это образцы состояний, не свидетельство серверной загрузки или сохранения данных.

Исходники находятся в `design/reference/ui-components.js`, `controls.js`, `controls.css`; композиция примеров — в `control-examples.js`. Реализован дизайн-прототип. Slider и Progress в библиотечном реестре сохраняют статус planned; Blade API не поставлен. Проверки и браузерная/визуальная приёмка этого изменения не выполнялись.
