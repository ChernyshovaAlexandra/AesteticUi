# Раздел «Компоненты» и атомарные элементы

Основание — U-CATALOG-01, прямое поручение пользователя от 23 октября 2026: понятная вкладка компонентов, атомарные элементы, правила подключения и размещения по UI/UX. Это описание реализации; постоянное требование хранится в `requirements.md`.

## Навигация и знания

Верхние разделы workbench — «Компоненты» и «Подключение». `/` и `/components` показывают обзор элементов, `/components/<id>` — конкретный элемент. `/installation` содержит локальное подключение Composer, Assets/Scope и обновление ассетов. Старые ссылки на конкретные компоненты сохранены.

Боковая навигация группирует элементы по задачам: действия, ввод данных, выбор и настройки, обратная связь, изображения и иконки. Scope/Page/Assets помещены отдельно в «Основу интерфейса». Начальная страница больше не является страницей Button. Убран длинный раскрывающийся перечень всех planned-семейств из основной навигации; сами записи реестра сохранены, прямые страницы planned-компонентов по-прежнему объясняют их недоступность.

Сведения хранятся в `catalog/components.json`:

- `componentGroups` и `catalogGroup` задают группировку.
- `displayName` — понятное русское название рядом с техническим именем.
- `guidance` — назначение, когда выбирать, где размещать, чего избегать, подписи и клавиатура.
- `installation` — общий порядок подключения; он не приписывается каждому компоненту заново.
- `api` и `previews` — написанный контракт и ссылки на исполняемые Blade-примеры.

Workbench рендерит общий layout, карточки обзора и страницы из этих данных. В карточке сначала идут правила UI/UX и пример подключения, затем темы/плотность/ширина, живые состояния и API. Preview и показываемый исходник остаются одним Blade-файлом. Текущий снимок содержит 26 сценариев; это описание исходников, не результат их проверки. Те же данные доступны будущему MCP, но сервер MCP пока не реализован.

## Написанные атомарные контракты

14 атомов имеют статус `experimental`: Icon, Button, Link, Spinner, Status, Input, Textarea, Select, Checkbox, Radio, Switch, FileInput, Avatar, Thumbnail. Вместе со Scope/Page/Assets это 17 контрактов. Опубликован Composer-релиз `0.1.0-alpha.1`; `libraryVersion=0.1.0-alpha.1`. Рендеринг проверен, но `runtimeVerified=false` сохраняется до полной проверки браузерных взаимодействий.

Все элементы — отдельные Blade-компоненты. Композиции примеров передают значения, подписи и слоты, а не содержат копии их разметки. Field/Form и серверные привязки остаются отдельной работой; примеры явно связывают нативные label, id, hint/error. Значения, old/errors и ACL передаёт приложение.

Input пока поддерживает text/email/password/search/tel/url/number. Нативные date/time picker через него не включаются. Собственные Calendar/TimePicker, а также rich editor, upload-preview, drag-and-drop, AvatarGroup и сложные композиции этим изменением не объявляются реализованными.

Button сохраняет primary/outline и получает loading через Spinner, aria-busy и disabled. Icon-only собирается тем же Button с Lucide в slot и aria-label на кнопке. Status получает семь смысловых тонов; ошибки и отмена различаются. Цвета Status используют CSS `light-dark()` и наследуемый `color-scheme` ближайшего Scope, включая вложенные области. Матрица браузерной совместимости не подтверждена.

Icon использует только оригинальный локальный набор Lucide из commit `20aef31db93fe4d9f398dbb15b120d99c48eef95`. Геометрия SVG не изменяется; provenance и upstream LICENSE находятся в `resources/icons/`. Сырые SVG читаются только из фиксированной пакетной карты, имя не выбирает произвольный файл. Иконки по умолчанию декоративны; самостоятельным задаётся label.

## JavaScript и Select

Assets поставляет один stylesheet и один ES module по manifest. Встроенной зависимости от Alpine/jQuery/React, CDN, Tailwind или сборки потребителя нет. Источники — `resources/css/aestetic-ui.css` и `resources/js/aestetic-ui.js`; готовая поставка находится в `dist/` и скопирована в локальный workbench.

Select — одиночный выбор из явно переданного массива `{value,label,disabled?}`. JS улучшает настоящий select своим trigger/listbox, сохраняет name/value/required/FormData, связывает подписи и ошибки, обрабатывает нативные change/reset и обновление options/disabled. Стрелки/Home/End перемещают активный вариант, Enter/Space выбирают, Escape/Tab закрывают, набор начала текста ищет вариант. Открытие поддерживает верх/низ и native Popover при доступности; без Popover используется позиционирование fixed. Multiple/optgroup/удалённый поиск этим контрактом не поддерживаются. Без JS остаётся оформленный нативный fallback, что не выдаётся за собственный раскрытый список.

Checkbox использует нативную семантику; mixed/indeterminate и сброс mixed задаются JS. Radio/Switch не посылают запросы автоматически. Avatar использует инициалы и необязательное изображение; JS возвращает fallback при ошибке картинки. Миниатюра статична и не притворяется галереей.

Runtime экспортирует `enhance(root)` и `destroy(root)`. При обычной загрузке страницы enhance запускается автоматически. При замене фрагментов приложение вызывает destroy до удаления и enhance после вставки. Модуль можно получить через `import(document.querySelector('script[data-aui-runtime]').src)`; повторное enhance не добавляет обработчики заново. Приложение управляет программными изменениями значений через стандартные события input/change. Отключение/cleanup описано контрактом, а не объявлено проверенным.

## Граница готовности

Изменены исходники, реестр, документация и локальная поставка ассетов. Проверки, validation builds, HTTP-запросы и браузерная приёмка новых атомов в этом задании не выполнялись. Ранее пользователь поручил запустить workbench и открыть вкладку; это не является доказательством корректности текущего изменения.

Во время редактирования открытого каталога новая навигация обратилась к ещё не сохранённому `componentGroups` и дала показанную пользователем ошибку 500. Добавлены сам раздел и согласованные назначения групп; реестр сохраняется через временный файл с заменой после подготовки данных. Исправление причины в исходниках не выдаётся за выполненную HTTP-проверку. Публикация и внешние проекты не затрагивались.

Ориентиры: [shadcn/ui Button](https://ui.shadcn.com/docs/components/button), [shadcn/ui Select](https://ui.shadcn.com/docs/components/select), [WAI APG Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/). Это ориентиры выбора/взаимодействия; фактический API Aestetic UI определяется собственным кодом и реестром.
