# Проверка переиспользования — 23 октября 2026

Объём: исходники дизайн-прототипа, его фактические потребители и имеющиеся четыре экспериментальных Blade-примитива. Основание — прямой запрос пользователя проверить, что остальные элементы являются отдельными переиспользуемыми компонентами.

## Найдено и изменено

| Область | Что мешало переиспользованию | Текущая граница |
| --- | --- | --- |
| Общие примитивы | Значительная часть renderer находилась в файле экранов, некоторые helpers были локальными | Общий `ui-components.js`, используемый экранами, примерами, контролами и медиакомпонентами |
| Таблицы | Три копии оболочки Table в списке и карточке клиента | Один `components.table` с header/body; предметные строки передаёт экран |
| Поля | Отдельные Field-обёртки формы клиента, создания заказа и примеров | Общие Field/Input/Select/Textarea; ID, значения, hint/error и атрибуты передаются снаружи |
| Вкладки | Список overview/orders/history был зашит в обработчик клавиатуры приложения | Общие Tabs и runtime, работающий с DOM своей группы; предметная подписка отдельно |
| Навигация и поверхности | Разметка дерева, breadcrumbs, оболочки и секций форм принадлежала файлу экранов | Общие renderers с деревьями/слотами; приложение готовит разрешённые пункты и контент |
| Диалог | Просмотр изображения повторял оболочку обычного диалога и отдельно управлял фокусом | Один Dialog renderer/runtime, состояние каждого dialog отдельно |
| Медиакомпоненты | Gallery/Slider/Viewer читали закрытый demo-массив photos; ImageBlock/Figure/состояния были HTML внутри примера | `media-components.js` не содержит demo-данных; примеры только передают свои items/слоты |
| Меню, состояния и характеристики | Меню примера, формы скелетонов и списки характеристик имели локальную разметку | Общие ActionMenu, LoadingSkeleton, DescriptionList, Timeline, ValidationSummary |

Select, Calendar/TimePicker, Tooltip и popup-runtime уже работали как общие DOM-enhancers. Их поведение не переписано: они переведены на общий источник Icon/escape. Текущие `assets`, `scope`, `page`, `button` в `resources/views/components/` принимают props/slots и атрибуты; зависимости от демо-заказов или фотографий при чтении этих шаблонов не обнаружено. Это не означает реализации остальных Blade-семейств.

## Прослеженная цепочка использования

- Список заказов и две таблицы клиента → `components.table`; строки и сортировка поступают от экрана.
- Редактирование клиента, создание заказа, поля примеров → `components.field`; label/hint/error принадлежат одному renderer.
- Карточка клиента и независимые примеры → `components.tabs` → `ui-runtime.js`; группа клиента обновляет приложение только через подписку на событие.
- Сетка, отдельная карточка и Carousel → `mediaCard`; Carousel получает готовые карточки и добавляет только оболочки слайдов.
- Медиапримеры → `mediaComponents.gallery/slider/imageBlock/figure`; набор photos остаётся только в примерах.
- Любое открытие фото → данные ближайшего медианабора → `openViewer` → общий Dialog и Slider.

## Выполненные проверки и ограничения

Проведён просмотр исходников и мест вызова, статический поиск предметных связей в общих модулях. `node --check` для 12 затронутых JavaScript-файлов завершился без ошибок синтаксиса. Команда разбирает исходники и не запускает интерфейс.

Дополнительно сопоставлены вызовы общих renderers в экранах/примерах и `prototype.entryPoint` реестра с экспортами соответствующих модулей. Отсутствующих точек входа не найдено. Это статическое сопоставление имён; значения props и выполнение событий оно не проверяет.

Браузер, тесты, typecheck, lint и сборка не запускались. Работа фокуса, свайпов, скролла, нескольких экземпляров и сохранение визуального вида требуют отдельной браузерной приёмки. Примеры таких состояний написаны, но наличие примера не является доказательством runtime-работоспособности.

Публикация, установка у потребителя и перенос медиасемейств/общих renderers в Blade не выполнялись. Библиотечные `planned`/`experimental` статусы сохранены. Описание прототипа в реестре не делает его доступным Composer API.
