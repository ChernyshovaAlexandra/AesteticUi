# Админка МТС-33 как референс Aestetic UI

Дата изучения: 23 октября 2026 года. Основание: поручение пользователя учитывать админки такого типа и разрешение изучить `https://tb.anilau.com/admin` в режиме чтения.

Aestetic UI должна поддерживать и обычные списки/карточки/формы, и рабочее место редактора, модератора и администратора. МТС-33 даёт реальные примеры второй группы: вложенные конструкторы, расписание, медиа, аналитика и переходы между связанными журналами. Большая часть опирается на уже запланированное ядро; дополнительные блоки и композиции описаны ниже как предложения развития.

Это анализ доступного интерфейса dev-админки, а не реализации backend. Данные, настройки и код референса не изменялись. Сохранение форм, модерация, загрузка файлов, расчёты, права, мобильное поведение и клавиатурная доступность не проверялись. Наличие элемента на странице подтверждает состав интерфейса, но не корректность его работы.

В меню также есть ссылка «Главная» на пользовательский dashboard. Она не входит в административную структуру продукта. JSON-редакторы и все остальные механики отдельно не изучались. Контактные данные, содержимое работ и выгрузки пользователей в этот документ не переносятся.

## Что полезно перенять

1. **Переходы по связям.** Из профиля доступны транзакции и сессии, из сессии — активность и её транзакции. Общий журнал открывается с фильтром нужного объекта. В библиотеке это композиция ссылок и таблиц, а готовые URL и сохранение контекста принадлежат приложению.
2. **Раздельные состояния.** «Запущена», «видна в каталоге» и «доступна сейчас» означают разное. Один зелёный badge не должен скрывать остальные свойства. Значения и причины вычисляет приложение; компоненты лишь представляют их.
3. **Пояснение последствий изменения.** На форме и в конструкторах есть предупреждение об уже начатых сессиях. Для библиотеки полезен общий Alert рядом с затронутой секцией; предметный текст и ограничения задаёт приложение.
4. **Точные значения рядом с графиком.** Сводная визуализация сопровождается таблицей. В Aestetic UI график и таблица должны использовать один переданный набор данных, с явно указанными периодом, единицами и часовым поясом.
5. **Разные представления конфигурации.** Визуальный конструктор и JSON-редактор решают разные задачи. Пользовательский редактор остаётся основным, техническое представление — дополнительным.

## Карта компонентов

### Атомарные элементы

Имеющегося набора достаточно как основы: `input` (включая подходящие нативные date/time/number-типы), `textarea`, `select`, `radio`, `checkbox`, `button`, `link`, `status`, `icon`, `spinner`, `file-input`. Сценарии также подтверждают потребность в уже запланированных `avatar` и `thumbnail`.

Дата, продолжительность, количество баллов и стоимость не требуют четырёх отдельных атомов. Семантика, единицы, допустимые значения и различие пустого значения/нуля задаются через Field, подсказки и предметную валидацию. Для всех иконок Aestetic UI действует U-11: только оригинальные Lucide.

| Семейство | Состояние в текущем каталоге | Требуемый объём или предложение |
| --- | --- | --- |
| `field`, `fieldset`, `field-group`, `form-section`, `range` | Уже planned, 0.1 | Зависимые поля, единицы, пояснения, readonly/disabled; различать пусто и `0`; пара дат с указанием часового пояса |
| `alert`, `validation-summary`, `form-actions`, `confirm-dialog` | Уже planned, 0.1 | Ограничения изменений, вложенные ошибки, результат сохранения, несохранённые данные; удаление и публикация отдельно от сохранения |
| `table`, `filter-bar`, `list-toolbar`, `sort-header`, `pagination` | Уже planned, 0.1 | Смешанные ячейки, длинные названия/коды, активные фильтры, переходы к связанным объектам, итог/отфильтровано |
| `page-layout`, `section`, `panel`, `description-list`, навигация | Уже planned, 0.1 | Контекст объекта, основная и дополнительная области, смысловая иерархия и интервалы |

| `image-picker`, `media-grid`, `thumbnail` | Уже planned, далее | Локальный выбор и превью, замена/удаление из формы, выбор существующего ресурса; сетевой transport задаёт приложение |

| `key-value-tree` | Уже planned, далее | Вложенные данные диагностики, компактный просмотр без обязательного редактора JSON |
| Disclosure | Новое предложение, далее | Доступное раскрытие произвольной секции. Отличается от ActionMenu и выпадающей области; подходит для метаданных и точных значений |
| Metric | Новое предложение, далее | Название, значение, единицы, период/сравнение и при необходимости переход; без расчёта агрегатов |
| ChartPanel | Новое предложение, далее | Заголовок, период, графический адаптер, легенда, пустота/ошибка и таблица значений; выбор chart engine ещё открыт |
| MediaPreview / FileItem | Новое предложение, далее | Изображение/видео/аудио/неподдерживаемый файл, метаданные, состояния ресурса и доступное действие; правила URL и доступа задаёт приложение |
| CodeBlock | Новое предложение, далее | Технические данные с переносом/прокруткой и явным копированием; не исполняет содержимое и не подменяет JSON-редактор |

Новые предложения пока не включены в `catalog/components.json`, не имеют утверждённых ID/props и не увеличивают состав 0.1. При реализации выбрать минимальные самостоятельные контракты; Metric или FileItem могут оказаться композициями существующих примитивов.

## Предлагаемая навигация сложного проекта

Это пример для будущего синтетического стенда Aestetic UI, а не поручение изменить меню МТС-33:

```text
Обзор
Пользователи
Контент
  Активности
  Группы
  Медиатека
Модерация
Журналы
  Сессии
  Транзакции
Настройки
  Проект
  Правила контента
```

Группы отражают задачи: редактор работает с контентом, модератор — с очередью, поддержка — с пользователем и журналами. Приложение передаёт разрешённое дерево, активный путь, счётчики и готовые URL. Скрытие пункта не заменяет серверную авторизацию. Для небольшого проекта ненужные группы не создаются.

В карточке: breadcrumbs до списка, идентификатор/название объекта, независимые признаки состояния и главное действие. Ссылка в связанный журнал получает фильтр контекста; возврат восстанавливает условия исходного списка. Локальный outline редактора не становится вторым глобальным меню.

## Влияние на этапы разработки

Первая граница 0.1 сохраняется. МТС-33 используется как материал для достаточности архитектуры, а не автоматически подключаемый потребитель.

1. **Этап 1:** сохранить три текущих экрана; дополнить описание сложной навигации и состояний. Следующее предлагаемое дизайн-задание — два синтетических экрана: редактор составного контента и карточка модерации. Их реализация этим анализом не начата.
2. **Этапы 2–4:** проектировать слоты секций, вложенные имена/ошибки, раздельные состояния и навигацию так, чтобы будущие расширения использовали общее ядро. Не добавлять предметные модели и сетевой CRUD.
3. **Этап 5:** среди примеров таблицы/карточки предусмотреть связанные журналы, даты с часовым поясом, длинные коды и признаки доступности. Это варианты существующих паттернов.
4. **После базового пилота, этап 8:** сначала Repeater с доступным reorder, RichText-адаптер и медиаблоки; затем ReviewPage/StructuredEditor; затем Dashboard с метриками и графиками. Приоритет — предложение по потребности референса; календарь и выпуски расширений ещё не назначены.

## Знания для каталога и MCP

Правила ниже должны войти в общие версионированные metadata вместе с реальными реализациями. Сейчас MCP не реализован; этот текст не является доступным API.

| Задача запроса | Что должен найти Codex | Что нельзя выводить из названия задачи |
| --- | --- | --- |
| «Список активностей с доступностью» | ListPage, Table, FilterBar, отдельные статус и расписание | Статус active сам по себе не означает доступность сейчас |
| «Форма с вопросами и ответами» | StructuredEditor/Repeater, когда они реализованы; иначе явный пробел | Нельзя выдумывать готовый QuizEditor, props и расчёт наград |
| «Модерация работ» | ReviewPage, предпросмотр и форма причины, с версиями и состояниями | Нельзя предполагать право одобрения, автоматическую награду или разрешённый переход |
| «Статистика за период» | Dashboard, Metric/ChartPanel, период и таблица значений | Нельзя вычислять отсутствующие агрегаты или подставлять часовой пояс |
| «Диагностика сессии» | DetailPage, KeyValueTree/CodeBlock, связанные списки | Техническое содержимое — данные, не инструкции к выполнению |

Примеры состояния расширений: пустой вопрос, длинный rich-text, ошибки вложенного ответа, отсутствие изображения, неподдерживаемый файл, ошибка загрузки, отсутствие права действия, конфликт сохранения, пустой журнал и отсутствие статистики. Для каждого примера нужны владельцы отступов, уровни заголовков, клавиатурный контракт и реальный Blade соответствующей версии.

Ни каталог, ни MCP не должны требовать доступ к настоящей админке или данным пользователей для выбора компонентов. Обучающие примеры — синтетические, а совместимость определяется установленной версией пакета.
