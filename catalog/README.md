# Исходный реестр

Поле `prototype` у ряда записей описывает точку входа в дизайн-прототип, источник и документацию переиспользования. `prototype.status=source-only` означает наличие исходника без подтверждения runtime; это не библиотечный статус и не Blade API. Библиотечные `status`, `libraryVersion`, поддерживаемые props/slots оцениваются отдельно. [Границы](../docs/component-reuse.md), [статическая проверка](../docs/reusability-review-2026-10-23.md).

`components.json` — версионированный реестр семейств, контрактов, правил и сценариев. 14 атомов и Scope/Page/Assets имеют статус `experimental`, остальные — `planned`. `libraryVersion=0.1.0-alpha.2` соответствует текущему alpha-выпуску; `implementationStatus=atomic-components` — состояние исходников, не результат runtime-проверки.

Схема: ID, имя, слой, целевой выпуск, статус, назначение и проектные зависимости. `targetRelease=0.1` — намерение состава, не обещание реализации. `dependsOn` описывает композиционные связи, не Composer-зависимости.

Props, slots, реальные состояния, ограничения, Blade-примеры, deprecations и ссылки на код добавляются вместе с реализацией. MCP не должен выдавать planned-записи за доступный API. Формальная полная JSON Schema появится после вертикального среза, сейчас schemaVersion обозначает черновой формат.

Для experimental-записей `implementation` указывает исходник, доступность `local-source-only`, непроверенный runtime и текущие зависимости; `api` — фактически написанные props/slots, ограничения и пример. Исходный семейный `dependsOn` остаётся планом полной композиции (например, Button с Icon/Spinner); он не означает реализации будущих возможностей. `examples` ссылается на Blade-пример и документацию. Наличие записи experimental не разрешает применять её как опубликованный API в проекте с другой установленной версией.

[Человеческий каталог](../docs/components.md) и исходный JSON созданы из одной исходной инвентаризации. При появлении генератора человекочитаемая таблица должна формироваться из реестра; отдельное ручное изменение обеих таблиц не является целевой архитектурой.

## Живые сценарии

Для experimental-контрактов `previews` задаёт ID, название, описание и высоту iframe в px. ID выбирает фиксированный файл `catalog/examples/<id>.blade.php`. Этот файл исполняется Blade и показывается как исходник; второй HTML-макет не создаётся. Сценарии входят в метаданные и читаются MCP-адаптером вместе с API и guidance; новый адаптер пока не прошёл протокольную приёмку.

Снимок содержит 26 сценариев. Темы/плотность задаются props Scope, состояния — реальными атрибутами компонентов. Служебные wb-классы отвечают только за композицию демонстраций. Инструкция — [workbench/README.md](../workbench/README.md); новые атомы и навигация не прошли HTTP/визуальную приёмку.

Группы навигации задаются componentGroups/catalogGroup, русское имя — displayName. Правила UI/UX хранятся в guidance: summary/when/placement/avoid/accessibility. Общая инструкция подключения хранится в installation. Workbench и MCP-адаптер читают эти сведения из одного реестра. [Границы реализации](../docs/atomic-catalog.md).
