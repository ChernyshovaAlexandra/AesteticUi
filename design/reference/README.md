# Этап 1: эталонные экраны

Основной локальный адрес на текущем компьютере: **[http://aesteticui.test](http://aesteticui.test)**. Valet направляет его непосредственно в `design/reference/`, где находится `index.html`.

Также можно открыть `index.html` напрямую в браузере вручную. Сборка, установка зависимостей и внешние ресурсы не нужны. Все стили, данные и скрипты лежат рядом. Агент браузер не открывал; HTTP и runtime-проверки не выполнял.

## Локальный адрес через Valet

На компьютере с установленным Valet привязка создаётся из папки `design/reference/` командой `valet link aesteticui`. Зона Valet должна быть `.test`. Привязка локальная и в Git не хранится; она не публикует прототип в интернете. Для первого этапа используется HTTP без настройки сертификата.

На текущем компьютере зарегистрирована пользовательская ссылка Valet `Sites/aesteticui` на эту папку. Системные настройки и остальные сайты не менялись. После появления настоящего Laravel-workbench адрес потребуется переключить на его публичную точку входа.

## Маршрут просмотра

1. **Заказы** — начальный экран. Найдите заказ, примените фильтры, выберите строки или откройте номер заказа.
2. Нажмите имя клиента в таблице — откроется **карточка клиента**. Переключите Обзор / Заказы / История.
3. Нажмите **Редактировать** — откроется **форма** с тремя секциями. Измените данные, сохраните либо попробуйте уйти без сохранения.
4. Вернитесь к заказам. Ссылка «Все заказы» в карточке показывает заказы только этого клиента.

В боковой панели есть **Параметры макета**: светлая/тёмная тема, обычная/компактная плотность, обычное/пустое/ошибочное/загрузочное состояние. На узкой ширине параметры доступны через меню навигации.

## Что реализовано в исходниках прототипа

- Общая оболочка, раскрываемая группа клиентов, breadcrumbs и мобильная навигация через native dialog.
- Поиск, статусы, диапазон дат, сортировка суммы/даты, размер страницы и пагинация.
- Выбор строк текущей страницы, indeterminate и локальное массовое изменение статуса.
- CSV-экспорт текущей выборки и локальное создание синтетического заказа.
- Три карточки на одном шаблоне, вкладки с keyboard-переключением и краткие сведения о заказе.
- Черновик формы, ошибки, счётчик заметки, сохранение в память и подтверждение потери изменений.
- Focus-стили, skip-link, доступные подписи, адаптивные композиции и reduced-motion правила.

Перечень описывает написанный код. Он не является отчётом о runtime-работоспособности, доступности, совместимости или визуальной приёмке.

## Граница макета

Это одноразовый кликабельный **дизайн-прототип**, а не Laravel-workbench, каталог библиотеки или источник её публичного API. Общие функции рендеринга здесь нужны, чтобы три макета использовали одинаковые элементы; они не являются будущими Blade-компонентами.

В этапе 2 согласованные композиции реализуются реальными Blade-компонентами. Будущий живой каталог рендерит именно их, не этот HTML/JS-прототип. Статусы компонентов основного каталога пока остаются `planned`.

Данные вымышлены и меняются только в памяти страницы. Перезагрузка возвращает исходный набор. Запросов к API, backend-операций, сохранения в браузерное хранилище и подключения MCP нет. Кнопка экспорта создаёт локальный CSV по явному нажатию пользователя.

## Файлы

- `index.html` — точка открытия и общие dialog/live-region контейнеры.
- `styles.css` — визуальная система и правила адаптации.
- `data.js` — синтетические клиенты и заказы.
- `views.js` — общая оболочка, элементы и три композиции макета.
- `app.js` — локальное состояние, переходы и взаимодействия.

Правила направления и карта переходов: [docs/reference-design.md](../../docs/reference-design.md).
